## Финальное решение: Apache Tika + Groq `openai/gpt-oss-20b`

**Архитектура:** PDF/DOC → Apache Tika (селфхост, извлечение текста) → Groq LLM (structured extraction) → JSON

**Модель:** `openai/gpt-oss-20b` — протестирована, результат:
- Скорость: **1.5 сек** на резюме (~8K токенов)
- Качество: все поля заполнены корректно, даты точные
- Цена: $0.075/$0.30 за 1M токенов → ~$0.0005 за резюме
- Fallback: `openai/gpt-oss-120b` (3 сек, чуть дороже, если 20b косячит)

**Лимиты (бесплатный тир Groq):** 500K RPD, 250K TPM → ~27 резюме/мин на один ключ
**Стратегия:** парсим при загрузке резюме (realtime, не batch — у Groq batch от 24ч). На старте ротация API-ключей, потом бизнес-тариф.

**Важно в промпте:** уровни языков задать как enum (native/fluent/B2/B1/A2/A1) для консистентности.

## Рассмотренные альтернативы

### Вариант A: platform.unstructured.io (SaaS) — отклонён
Платформа с AI extraction — задаём JSON-схему, их ИИ заполняет при обработке документа.
- **Цена:** $0.03/страница. При 300 резюме на вакансию = ~$9 за просмотр
- **Причина отказа:** дорого при объёмах, под капотом тот же LLM + промпт — нет смысла платить за обёртку

### Вариант B: селфхост unstructured + Groq — запасной
Селфхост open-source unstructured (извлечение текста) + Groq.
- **Цена:** ~$0.0005/резюме
- **Минус:** тяжёлые Python-зависимости, лишний overhead — Tika проще и легче

### Вариант C: Apache Tika + Groq LLM — выбран ✓
Apache Tika (извлечение текста, Java, 15+ лет, Apache Foundation) + Groq (structured extraction). https://github.com/apache/tika
1. Запуск Tika-сервера: `docker run -p 9998:9998 apache/tika`
2. Из бэкенда POST файл → `http://localhost:9998/tika` → получаем текст
3. JSON-схему берём идентичную HH.ru. Текст из Tika → Groq LLM с промптом + схемой → структурированный JSON
4. Тестовые запросы, сравниваем качество с HH.ru парсингом
- **Цена:** ~$0.002/резюме (только Groq). Tika бесплатна. При 300 резюме = ~$0.60
- **Плюс:** лёгкий Docker-контейнер, 1000+ форматов, REST API (работает с любым бэкендом без Python), зрелый проект (15+ лет), встроенный OCR через Tesseract
- **Минус:** извлекает только плоский текст без структуры (но LLM разберётся сам)
- **Почему лучше варианта B:** не нужен Python, легче, стабильнее, больше форматов, проще интеграция (один HTTP-запрос)



# Парсинг резюме: сравнение подходов

## Проблема

Обычный regex-парсинг не понимает контекст — путает личный сайт кандидата с сайтом работодателя, берёт абсурдные значения в поля. Нужен подход на основе LLM.

---

## Рекомендуемая архитектура

```
PDF/DOC → Извлечение текста (бесплатно) → LLM (structured extraction) → JSON
```

---

## Сравнение вариантов

### Вариант 1: Groq + простой текстовый парсер

**Схема:** достаёшь текст (pdf-parse, python-docx) → кидаешь в Groq LLM → получаешь JSON

| Параметр | Значение |
|----------|----------|

| Цена | ~$0.002 за резюме ($2 за 1000 шт.) |
| Гибкость | Полный контроль через промпт |

**Плюсы:**

**Минусы:**

### Почему LiteParse не подходит даже при бэке на Node.js/Next.js

Несмотря на то что LiteParse — npm-пакет и нативно работает в Node.js:
1. Тянет тяжёлые зависимости в процесс Next.js (PDF.js, Tesseract WASM, LibreOffice)
2. Раздувает билд и память сервера
3. Качество парсинга на том же уровне что Tika
4. Tika изолирован в Docker-контейнере, вызывается одним HTTP-запросом:

```ts
const text = await fetch('http://localhost:9998/tika', {
  method: 'PUT',
  headers: { 'Accept': 'text/plain' },
  body: fileBuffer,
}).then(r => r.text());
```

### Решение

**Остаёмся на Apache Tika + Groq.** Причины:

1. Резюме — простые документы (90% одноколоночный текст), Tika справляется
2. Минимальная стоимость: ~$0.002/резюме
3. Нет лишних внешних зависимостей, Tika работает без интернета
4. LiteParse не даёт преимуществ перед Tika, только добавляет bloat в Node.js

**Когда пересмотреть:** если начнут массово приходить сканированные PDF или резюме с таблицами/сложным форматированием — добавить LlamaParse Agentic как fallback для «сложных» документов (гибридный подход), Tika оставить для простых.
